# 非リエントラント性

RTIC では、タスクハンドラは*リエントラントではありません*。タスクハンドラに再入すると、
Rust のエイリアシング規則を破り、*未定義動作*につながるおそれがあります。タスクハンドラは
次の 2 つの方法のいずれかで再入される可能性があります。ソフトウェアによる場合と、ハードウェアによる場合です。

## ソフトウェアによる場合

ソフトウェアによってタスクハンドラに再入するには、その基盤となる割り込みハンドラを
FFI を使って呼び出す必要があります（以下の例を参照）。FFI には `unsafe` コードが必要なため、
エンドユーザーが割り込みハンドラを直接呼び出すことは推奨されません。

``` rust,noplayground
#[rtic::app(device = ..)]
mod app {
    #[init]
    fn init(c: init::Context) { .. }

    #[interrupt(binds = UART0)]
    fn foo(c: foo::Context) {
        static mut X: u64 = 0;

        let x: &mut u64 = X;

        // ..

        //~ この時点で `bar` は `foo` をプリエンプトできる

        // ..
    }

    #[interrupt(binds = UART1, priority = 2)]
    fn bar(c: foo::Context) {
        extern "C" {
            fn UART0();
        }

        // この割り込みハンドラはタスクハンドラ `foo` を呼び出し、
        // 静的変数 `X` のエイリアシングを引き起こす
        unsafe { UART0() }
    }
}
```

RTIC フレームワークは、ユーザー定義のタスクハンドラを呼び出す割り込みハンドラコードを
生成しなければなりません。私たちは、これらのハンドラがユーザーコードから呼び出せないように
慎重に設計しています。

上の例は次のように展開されます。

``` rust,noplayground
fn foo(c: foo::Context) {
    // .. ユーザーコード ..
}

fn bar(c: bar::Context) {
    // .. ユーザーコード ..
}

mod app {
    // このブロック内のすべてはユーザーコードからは見えない

    #[no_mangle]
    unsafe fn USART0() {
        foo(..);
    }

    #[no_mangle]
    unsafe fn USART1() {
        bar(..);
    }
}
```

## ハードウェアによる場合

タスクハンドラは、ソフトウェアの介在なしでも再入されることがあります。これは、
同じハンドラがベクタテーブル内で 2 つ以上の割り込みに割り当てられている場合に発生しえますが、
RTIC フレームワークにはこの種の設定のための構文はありません。
