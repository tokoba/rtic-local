# 天井解析

リソースの *優先度天井*（以降、単に *天井*）とは、任意のタスクがリソースメモリに安全にアクセスするために必要な動的優先度です。天井解析は比較的単純ですが、RTICアプリケーションのメモリ安全性にとって重要です。

リソースの天井を計算するには、まずそのリソースにアクセスできるタスクの一覧を集める必要があります -- RTICフレームワークはコンパイル時にリソースへのアクセス制御を強制するため、この情報にもコンパイル時にアクセスできます。リソースの天井は、単にそれらのタスクの中で最も高い論理優先度です。

`init` と `idle` は正式なタスクではありませんが、リソースにアクセスできるため、天井解析では考慮する必要があります。`idle` は論理優先度 `0` を持つタスクとして扱われますが、`init` は解析から完全に除外されます -- その理由は、`init` が静的変数にアクセスする際にクリティカルセクションを決して使用せず（また必要としない）からです。

前の節では、共有リソースは、それにアクセスできるタスクに応じて、一意な参照 (`&mut-`) として現れる場合もあれば、プロキシ越しに現れる場合もあることを示しました。どちらがタスクに渡されるかは、タスク優先度とリソースの天井によって決まります。タスク優先度がリソースの天井と同じであれば、タスクはリソースメモリへの一意な参照 (`&mut-`) を取得し、そうでなければタスクはプロキシを取得します -- これは `idle` にも当てはまります。`init` は特別で、常にリソースへの一意な参照 (`&mut-`) を取得します。

天井解析を説明する例を示します:

``` rust,noplayground
#[rtic::app(device = ..)]
mod app {
    struct Resources {
        // `foo` (prio = 1) と `bar` (prio = 2) がアクセスする
        // -> 天井 = 2
        #[init(0)]
        x: u64,

        // `idle` (prio = 0) がアクセスする
        // -> 天井 = 0
        #[init(0)]
        y: u64,
    }

    #[init(resources = [x])]
    fn init(c: init::Context) {
        // これは `init` なので一意な参照
        let x: &mut u64 = c.resources.x;

        // これは `init` なので一意な参照
        let y: &mut u64 = c.resources.y;

        // ..
    }

    // 優先度 = 0
    #[idle(resources = [y])]
    fn idle(c: idle::Context) -> ! {
        // 優先度 (0) == リソースの天井 (0) なので一意な参照
        let y: &'static mut u64 = c.resources.y;

        loop {
            // ..
        }
    }

    #[interrupt(binds = UART0, priority = 1, resources = [x])]
    fn foo(c: foo::Context) {
        // タスク優先度 (1) < リソースの天井 (2) なのでリソースプロキシ
        let x: resources::x = c.resources.x;

        // ..
    }

    #[interrupt(binds = UART1, priority = 2, resources = [x])]
    fn bar(c: foo::Context) {
        // タスク優先度 (2) == リソースの天井 (2) なので一意な参照
        let x: &mut u64 = c.resources.x;

        // ..
    }

    // ..
}
```
